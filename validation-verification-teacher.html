Teacher Guide: Validation, Verification & Tracing

Six validation checks (RLTPFC), three verification methods, check digits, tracing a REPEAT validation loop and runnable 0478 checks.

60:00
Ready

Lesson overview

Learning objectives

  • Name, describe and give an example of all six validation checks
  • Distinguish validation from verification and describe three verification methods
  • Calculate and use an ISBN-10 check digit
  • Trace and write validation routines in 0478 pseudocode

Success criteria

  • I can recall RLTPFC with an example for each
  • I can explain why validation can't prove data is correct
  • I use REPEAT…UNTIL for a validation loop
  • My check code runs and gives the right output

Prior knowledge

  • REPEAT…UNTIL, IF…ELSE…ENDIF
  • Arrays indexed from 1
  • LENGTH, SUBSTRING
  • Trace tables (Week 9)

Keywords

validation, verification, range, length, type, presence, format, check digit, double entry, visual check, boundary

Sum 130 · 130 MOD 11 = 9 · check digit = 11 − 9 = 2 → ISBN 0-306-40615-2

Part 2: Be the scanner

Three missions tick automatically:

  1. Scan 0306406152 → valid
  2. Change one digit, e.g. 0306406162 → caught
  3. Swap two neighbours, e.g. 0306406512 → caught
ISBN-10 always catches a single wrong digit and a swap of two neighbouring digits. That's why the weights are all different.

If the remainder is 0, the check digit is 0. If 11 − remainder = 10, the check digit is written X.

SupportDo the first three products together on the board.
Stretch"Find a typo that is not caught." (Two separate wrong digits can cancel out. For example, 1806406152 changes the 1st digit by +1 (+10) and the 2nd by +5 (+45). That adds 55, a multiple of 11, so the scanner says VALID.)

Activity C: Trace the validation loop

22–28 min
DECLARE Score : INTEGER
DECLARE Attempts : INTEGER
Attempts ← 0
REPEAT
   INPUT Score
   Attempts ← Attempts + 1
   IF Score < 0 OR Score > 100 THEN
      OUTPUT "Invalid"
   ENDIF
UNTIL Score >= 0 AND Score <= 100
OUTPUT "Accepted after ", Attempts
PassScoreAttemptsOUTPUT
11501Invalid
2-52Invalid
31003—

Final OUTPUT: Accepted after 3 · never read: 42

100 is a boundary value. Exam test-data questions want normal, abnormal (erroneous), boundary and extreme data. 150 and -5 are abnormal; 100 is boundary/extreme.

Think–pair–share model answer: REPEAT…UNTIL tests the condition at the end, so the input is always asked for at least once. A WHILE loop tests first, so it needs an INPUT before the loop and a second INPUT inside it.

Students who write a 4th row for 42. The trace stops when the UNTIL condition becomes TRUE.

Challenge 1 — Presence 
FOR i ← 1 TO 3
   Count ← 0
   FOR j ← 1 TO LENGTH(Names[i])
      IF SUBSTRING(Names[i], j, 1) <> " " THEN
         Count ← Count + 1
      ENDIF
   NEXT j
   IF Count = 0 THEN
      OUTPUT "MISSING"

   ENDIF
NEXT i

Activity E: Full Paper 2 questions (6 marks each)

38–50 min

About 6 minutes per question, in silence and exam conditions. Students can try their code with their own test inputs. Mark my answer runs it against hidden examiner test data and ticks the mark points. Code that doesn't run with the examiner data scores 0. The model answer and trace unlock after marking.

Every bullet in the question is a mark point. Tick them off on the question as you write.

Question 1 — Whole-number validation [6]

Input one number at a time; store whole numbers in Accepted[]; re-ask until whole; after 15 stored, output a completion message; clear prompts.

#Mark point (max 6)
1A loop that runs for 15 inputs
1Input of a number
1A test for a whole number, e.g. MOD, DIV or ROUND
1Repeated re-input while the number is not whole, until it is whole
1Storing the whole number in the correct array element
1At least two outputs seen: input prompt, error message or completion message

Accepted whole-number tests: ROUND(Number, 0) = Number, MOD(Number, 1) = 0, DIV(Number, 1) = Number.

Examiner test data (hidden from students): 4.5, 7, -3, 0.25, 12, 5, 8, 1, 0, 100, 2.5, 33, 6, 9, 11, 14, 20, 2. That is 3 non-whole and 15 whole numbers, so all 18 inputs must be used and Accepted[] must hold 7, -3, 12 … 2.

Model answer 
FOR Counter ← 1 TO 15
    REPEAT
        OUTPUT "Please enter whole number ", Counter, " of 15"
        INPUT Number
        IF ROUND(Number, 0) <> Number
            THEN
                OUTPUT "That is not a whole number, please enter it again"
        ENDIF
    UNTIL ROUND(Number, 0) = Number
    Accepted[Counter] ← Number
NEXT Counter
OUTPUT "The check has been completed: 15 whole numbers have been stored"

Counter ← Counter + 1 inside the FOR loop. It skips every other element, and the auto-marker flags it by name. Also watch for Number declared as INTEGER: the runner rejects 4.5 with a type error, so it must be REAL.

Question 2 — Password validation and verification [6]

Length check (≥ 10 characters, re-ask until valid), then double-entry verification; restart from step 1 on mismatch; no declarations.

#Mark point (max 6)
1First input of the new password
1Checking the length of the new password
1Re-entering the password if the length check fails, until it passes
1Second input of the new password …
1… and checking that it matches the first input
1Restarting the whole process, as many times as needed, if verification fails
1At least two outputs seen: input prompt, error messages or acceptance message

Examiner test data (hidden):
Test 1 (the trace): sunny, riverbank22, riverbank2, riverbank22, riverbank22
Test 2 (length re-checked after restart): short, abcdefghij, abcdefghik, x, abcdefghij, abcdefghij
Test 3 (two short entries): sunny, abc, riverbank22, riverbank22
Each test must use every input and end with exactly one "accepted" message.

A WHILE loop with a priming INPUT is also accepted for the length check.

Paper 1 style written question

50–54 min

Students write an answer (at least 30 words unlocks marking), then self-mark against the scheme. Silent, exam conditions.

Mark scheme — 4 marks

1Range check: data must be within a min–max range, with an example (e.g. age 11–18)
1Length check: data must have a specific number of characters, with an example (e.g. password 8–20 characters)
1Type check: data must be a specific data type, with an example (e.g. age must be an integer)
1Validation only checks data is reasonable, not that it is true — e.g. age 15 passes even if the real age is 16

Accept a presence check as one of the three in (a). Max 3 for (a). No mark for a check named without an example.

Spot-check two answers aloud. Is every "check" paired with an example?

Common misconceptions

MisconceptionQuick fix
"Validation makes sure data is correct"Age 25 vs real 26 — passes every check. Only verification could catch it.
Naming a check with no exampleExam marks need both — make them say "…for example…" every time.
Range vs length confusionRange = the value (0–100). Length = how many characters (8–20).
Double entry seen as validationIt compares two entries for a match — that's verification.
Exclusive boundaries (> 0 AND < 100)Test with 0 and 100 — both must be accepted when the range is "0 to 100".
Validation loop as WHILE with no priming inputUse REPEAT…UNTIL; it always runs once.
Python in Paper 2 (try/except, strip, ==)The runner rejects them with a message — point students to it.
