Lesson overview

Learning objectives

  • Write totalling, counting, max, min and average algorithms in 0478 pseudocode
  • Trace a standard-method algorithm accurately
  • Identify and fix common initialisation errors

Success criteria

  • I initialise totals/counters to 0 before the loop
  • I initialise Max/Min from List[1]
  • I calculate the average after the loop with /
  • My code runs and gives the right output

Prior knowledge

  • 1D arrays indexed from 1
  • FOR…NEXT, IF…THEN…ENDIF
  • Assignment with ←

Keywords

totalling, counting, initialise, iteration, trace table, linear search

2

The five patterns (mini-lesson)

5–12 min

Short teacher input using the pattern cards, then students run all three worked examples (tabs). Keep the talk under 4 minutes.

Every one of these has three parts: set it up before the loop, update it inside the loop, use it after the loop. If you remember nothing else, remember that.

Quick-fire questions (cold call):

  1. Why is Max ← 0 dangerous? If all values are negative, Max stays 0.
  2. What goes wrong if Total ← 0 is inside the loop? It resets every pass; only the last value is kept.
  3. Why / and not DIV for an average? DIV drops the decimal part.

Predict-then-run: students change one array value and predict the output before running. Expected outputs: Totalling 438, Counting 3, Max/Min/Avg 31, 15, 21.6.

Students writing == or Python for score in scores. The runner flags both — use the error message as a teaching moment.

Think–pair–share model answer

If every value is negative (e.g. −4, −9, −2), Max ← 0 is never beaten, so the algorithm outputs 0 — a value that isn't even in the list. Starting from Data[1] guarantees Max is always a real element.

Note: on Paper 2 trace tables students often only write a value when it changes. The student page asks for the value every row to keep auto-checking simple — mention that both conventions are accepted.

SupportPoint to row 3 only: "Is 12 bigger than 7? So what happens to Max?"
Stretch"Rewrite it so it also tracks Min. What row does Min change in?" (Row 2, Min = 3)
4

Activity B: Code jigsaw (Parsons problem)

20–27 min

Students build a "count scores ≥ 90" algorithm from shuffled lines, avoiding three traps, then run it.

Correct solution (output 2)

CountHigh ← 0
FOR i ← 1 TO 5
   IF Scores[i] >= 90 THEN
      CountHigh ← CountHigh + 1
   ENDIF
NEXT i
OUTPUT CountHigh

The three traps

  • CountHigh ← CountHigh + Scores[i] — totalling, not counting
  • IF Scores[i] == 90 THEN — Python operator and only matches exactly 90
  • CountHigh ← 1 — counter must start at 0
Before you check — say out loud why each line you left in the bank is wrong.
SupportTell them the first and last lines; they place the middle five.
Stretch"Change it to count scores between 80 and 89 inclusive." (IF Scores[i] >= 80 AND Scores[i] <= 89 → 2)

Model answers

Challenge 1 — Total (438) 
Total ← 0
FOR i ← 1 TO 5
   Total ← Total + Scores[i]
NEXT i
OUTPUT Total
Challenge 2 — Count A's (3) 
CountA ← 0
FOR i ← 1 TO 8
   IF Grades[i] = "A" THEN
      CountA ← CountA + 1
   ENDIF
NEXT i
OUTPUT CountA
Challenge 3 — Max & min (31, 15) 
Highest ← Temps[1]
Lowest ← Temps[1]
FOR i ← 2 TO 7
   IF Temps[i] > Highest THEN
      Highest ← Temps[i]
   ENDIF
   IF Temps[i] < Lowest THEN
      Lowest ← Temps[i]
   ENDIF
NEXT i
OUTPUT Highest
OUTPUT Lowest
Challenge 4 — Linear search (4) 
Index ← 1
Found ← FALSE
WHILE Found = FALSE AND Index <= 5 DO
   IF Names[Index] = "Zoe" THEN
      Found ← TRUE
   ELSE
      Index ← Index + 1
   ENDIF
ENDWHILE
OUTPUT Index

A FOR loop that outputs the index when found also gives 4, but doesn't "stop when found" — award output marks, not the stopping mark.

⭐ Stretch — Above average (21.6, 3) 
Total ← 0
FOR i ← 1 TO 7
   Total ← Total + Temps[i]
NEXT i
Average ← Total / 7
Above ← 0
FOR i ← 1 TO 7
   IF Temps[i] > Average THEN
      Above ← Above + 1
   ENDIF
NEXT i
OUTPUT ROUND(Average, 1)
OUTPUT Above

Two loops are needed because you can't know which values are "above average" until the average exists.
