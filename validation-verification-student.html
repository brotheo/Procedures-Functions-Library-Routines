Checking Data: Validation, Verification & Tracing

Good programs refuse silly data and double-check important data. Today you'll name the six validation checks, crack a check digit, trace a validation loop and write checks that actually run.

1

Starter: Sensible or correct?

5 min

For each situation, decide whether it is validation (the computer checks the data is reasonable) or verification (checking the data is what was intended).

2

The six checks: RLTPFC

7 min

Cambridge expects you to know all six. Click each card to reveal an example — then cover the screen and recite them to your partner.

Exam tip: always name the check AND give an example — each mark needs both.

Validation — is it reasonable?

  • Done automatically by the computer
  • Happens before data is processed
  • Age 250 → rejected. Age 25 when you're really 26 → accepted!

Verification — is it what was intended?

  • Double entry: type it twice, the system compares
  • Visual check: "You entered John Smith. Correct? (Y/N)"
  • Proofreading: a person reads it through

Worked examples — they really ask for input

Try it: The Test inputs box feeds each INPUT in order (one per line; an empty line is a blank entry). Run each example, then change the inputs so the loop asks exactly three times before accepting.
